<task type="auto">
  <name>Task 2: Implement password utilities and registration API</name>
  <files>src/utils/password.ts, src/routes/auth/register.post.ts</files>
  <action>
    1. Create `src/utils/password.ts`:
       - hashPassword(password): uses bcrypt with cost factor 12
       - verifyPassword(password, hash): bcrypt.compare
       - passwordSchema: Zod schema requiring 8+ chars, uppercase, lowercase, number

    2. Create `src/routes/auth/register.post.ts` with two endpoints:
       - POST /api/auth/register/email:
         - Accept {email, password, username?}
         - Validate email format using Zod
         - Validate password using passwordSchema
         - Check email uniqueness
         - Hash password with bcrypt cost 12
         - Insert user into database
         - Return {userId, email} (no password)
         - Create audit log entry

       - POST /api/auth/register/phone:
         - Accept {phone, code, password, username?}
         - Validate phone format (11-digit Chinese phone: /^1[3-9]\d{9}$/)
         - Verify SMS code from sms_codes table (check exists, not used, not expired)
         - Mark code as used after verification
         - Validate password
         - Check phone uniqueness
         - Hash password and create user
         - Return {userId, phone}
         - Create audit log entry

    Both endpoints should use the Knex client for database operations.
  </action>
  <verify>

    Expected: 201 with userId, or 400/409 for validation errors
  </verify>
  <done>
    - Password hashing utility works correctly
    - Email registration creates user with hashed password
    - Phone registration validates SMS code before creating user
    - Duplicate email/phone returns 409 Conflict
    - Invalid input returns 400 Bad Request with validation errors
    - Audit log entries created for each registration attempt
  </done>
</task>

<task type="auto">
  <name>Task 3: Implement login API with JWT token generation</name>
  <files>src/routes/auth/login.post.ts</files>
  <action>
    Create `src/routes/auth/login.post.ts` with POST /api/auth/login:

    1. Accept {email?, phone?, password} - either email or phone required
    2. Validate password format using passwordSchema
    3. Find user by email or phone
    4. Check account lock status (locked_until > now means locked)
    5. Verify password using bcrypt.compare
    6. Handle failed login:
       - Increment failed_login_attempts
       - Lock account if attempts >= 5 (locked_until = now + 30 minutes)
       - Log failed attempt to audit_logs
       - Return 401 with generic "Invalid credentials" message
    7. On success:
       - Reset failed_login_attempts to 0
       - Generate access token: JWT with {sub: userId, email, phone, iat, exp}, 15min expiry, HS256
       - Generate refresh token: JWT with {sub: userId, type: "refresh"}, 7day expiry, HS256
       - Hash refresh token and store in refresh_tokens table
       - Log successful login to audit_logs
       - Return {accessToken, refreshToken, user: {id, email, phone, username}}

    Use environment variables: JWT_SECRET, ACCESS_TOKEN_EXPIRY (15m), REFRESH_TOKEN_EXPIRY (7d)
  </action>
  <verify>
    <automated>curl -X POST http://localhost:60000/api/auth/login -H "Content-Type: application/json" -d '{"email":"test@example.com","password":"Test1234"}'</automated>
    Expected: 200 with accessToken (JWT), refreshToken (JWT), and user object
  </verify>
  <done>
    - Login with valid credentials returns JWT tokens
    - Access token expires in 15 minutes
    - Refresh token expires in 7 days
    - Invalid credentials return 401 (same message for "user not found" and "wrong password")
    - 5 failed attempts locks account for 30 minutes
    - Successful login resets failed attempt counter
    - Refresh token stored hashed in database
  </done>
</task>
